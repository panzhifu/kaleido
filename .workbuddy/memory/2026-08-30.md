### 确认的关键问题（均为读码所得，未经编译验证）
1. **桌面端与服务层断开**：`apps/desktop/src/main.rs` 只声明 8 个 mod，`panels/`、`messages/`、`theme.rs` 是未编译的孤儿文件。`app.rs` 里 `KaleidoApp` / `AsyncImageLoader` / `BackgroundSaver` 三个字段都带 `#[allow(dead_code)]`，ImageStore / HistoryKeeper / ToolRegistry 零调用。toolbar 用 `modes.rs` 的硬编码枚举而非 ToolRegistry，且按钮无 `on_click` → GUI 里编辑链路和 undo 完全不存在。
2. **图层类型重复定义**：`layer.rs` 与 `layer_types.rs` 各自定义了 `LayerId` / `BlendMode` / `LayerContent` / `Layer`，各有独立的 `NEXT_LAYER_ID` 静态计数器。lib.rs 从两个模块分别 re-export（`LayerStack` ← layer，`Layer` ← layer_types），导致 `kaleido_services::Layer` 无法放进 `kaleido_services::LayerStack`。benches 用 `layer::*`，blend.rs 用 `layer_types::*`。
3. **混合模式有三份实现**：blend.rs（layer_types::BlendMode 用）、layer.rs 内联一份、blend_simd.rs 一份。
4. **blend_simd.rs `overlay_channel_simd:149` 运算符优先级 bug**：`val_255() - (...) >> 7` 应为 `val_255() - ((...) >> 7)`（`-` 优先于 `>>`），Overlay 亮部结果错误。同行 `255>>1` 当 128 用（实为 127）。
5. **`define_tool!` 宏生成不可编译代码**（sdk/lib.rs:158）：`apply` 签名写成 `&TiledImage`，Tool trait 要求 `&mut TiledImage`。宏无测试。
6. **op_graph ROI 是空壳**：`execute` 里 `let roi = if node_id == output_id { output_roi } else { output_roi };` 两分支相同；`FusedOp` 从未被 executor 调用（README 宣称的 point-op fusion 不存在）；`execute_node_parallel` 合并时用 `rect.x + px` 写入以 0 为原点的 output，roi.x≠0 时错位（测试只覆盖 roi.x=0）。
7. **`cordis_plugins.rs:142`**：`ai_agent_plugin` 文档说依赖 image_store + tool_registry，但 `Inject::new(["image_store"])` 漏了 tool_registry，闭包内却 `resolve_tool_registry(&ctx)?`。
8. **`TileSnapshotCommand::apply_before/after`**（tile_history.rs:199/211）：`data.clear() + extend_from_slice(空 Vec)` 会把 tile 数据长度清零，`from_diff` 的 `unwrap_or_default()` 正是空 Vec → 后续 `get_pixel` 会越界 panic。
9. `HistoryKeeperImpl::history_list` 的 `timestamp` 用 `SystemTime::now()`（非真实操作时间），`image_size` 恒为 (0,0)。
10. `wasm_host.rs` 的 `host_emit_event` 只打日志，没有真正转发到 Cordis（ctx 是 `#[allow(dead_code)]`）。WIT 定义的 `host-functions` 与实际 C ABI 也不一致。

### 本轮踩到的 GPUI API 坑（重要，下次直接用）
1. `Pixels` 字段私有（`pub(crate) f32`），**不能用 `.0`**，必须 `f32::from(pixels)`（有 `impl From<Pixels> for f32`）
2. 事件回调签名 `Fn(&MouseDownEvent, &mut Window, &mut App)` —— 是 `&mut App` 不是 `Context<T>`，所以刷新用 **`window.refresh()`** 而非 `cx.notify()`
3. `on_mouse_up` 只在元素内释放时触发（`hitbox.is_hovered`），**必须配 `on_mouse_up_out`** 兜底，否则笔画会卡在 active 状态
4. 闭包参数类型要么全标注要么全推断，**不能混**（`|e: &T, window, cx: &mut App|` 报错）
5. `notify()` 属于 `Context<T>` 不是 view；`entity.update(cx, |_v, cx| cx.notify())`
6. `Button::on_click` **返回 Self，必须重新赋值**（`b = b.on_click(..)`），否则 handler 丢失（mode_bar.rs 原本就是错的）
7. 没有通用的"取元素 bounds"API（`element_bounds` 只属于 InputHandler），窗口→图像坐标只能靠 `window.viewport_size()` + 布局常量（canvas.rs 顶部常量，需与 app.rs 布局保持一致）
8. `Arc<dyn Tool>`/trait object 调方法**不需要** trait 在 use 作用域内（会 unused import 警告）

## Bug 修复：打开文件无反应（2026-08-30 用户实测反馈）

### 根因（重要，易复发的坑）
scheduler 的 `Task` 文档明确："If you drop a task it will be cancelled immediately."（crates/scheduler/src/executor.rs:377）
我写了 `let _ = cx.spawn(async move |cx| {...})` → **Task 被立即 drop → 任务被取消** → await 对话框结果、打开图片的代码从未执行。
而文件对话框是**平台侧 detach 的任务**弹的（gpui_linux platform.rs prompt_for_paths → `foreground_executor().spawn(...).detach()`），所以对话框照常弹出、照常选择，但结果发给 channel 后无人接收 → 表现为"选了照片但没打开"。

### 修复
- app.rs 两处：`let _ = cx.spawn(...)` → `cx.spawn(...).detach()`（任务继续运行、不取结果）
- **以后所有 fire-and-forget 的 spawn 一律用 `.detach()`，绝不能 `let _ =`**

### 顺带：错误可见性
- status_bar.rs 新增 `show_message(text, is_error)` 机制（message 字段，错误红色 0xe5484d）
- 打开/保存/另存为的结果都显示到状态栏（"已打开 xxx.png (1920x1080)" / "打开失败: ..."），不再只 eprintln 到终端

### 排查中确认的其他链路（均正常，无需改）
- gpui_linux default features = ["wayland","x11"]，ashpd portal 对话框可用；返回普通 PathBuf（uri.to_file_path()）
- image crate 0.25 无 extra features：HEIC/AVIF 不支持（会报"打开失败"到状态栏，这是预期行为）

- **LayerId/BlendMode 上移到 traits**（kaleido-traits/src/layer.rs 新文件）：插件不再依赖 services 就能用图层类型。services/layer_types.rs 改为 `pub use kaleido_traits::{BlendMode, LayerId}`；所有 `BlendMode::X.blend()` 调用改为自由函数 `crate::blend::blend(mode, src, dst)`（layer.rs composite + tests + benches）
- **LayerInfo**（traits）：id/name/visible/opacity/blend_mode/is_pixels 轻量快照
- **LayerStore trait**（traits）：layers/active_layer/set_active_layer/**import_image**/add_pixel_layer/add_solid_layer/remove_layer/reorder/set_opacity/set_visible/set_blend_mode/set_layer_name/edit_active_layer/composite/document_size——插件操作图层的完整网关，方法全 &self（内部 Mutex）
- **Tool 契约扩展**：`supports_layers()` 默认 false + `apply_to_document(&mut dyn LayerToolContext, params)` 默认 Err——旧插件（brightness/invert/brush）零影响
- **LayerToolContext trait**：layer_store() + document_width/height

### C2 services 实现
- **LayerStoreImpl**（layer_store.rs 新）：Mutex<Inner{stack: Option<LayerStack>, active}> + Weak<dyn ImageStore> + Cordis ctx；每次修改 → publish()（composite → set_image 写回 ImageStore → 画布自动刷新）；发 layer_added/layer_removed 事件（KaleidoEmitter）
- **坑**：① composite() 返回**缓存引用**，publish 必须 `.clone()` 后释放锁 ② edit_active_layer 直接改像素后必须 `stack.invalidate()`（LayerStack 缓存机制）否则合成不更新 ③ push_layer 新层无条件成为活动层（PS 语义）
- cordis_plugins.rs 加 layer_store_plugin（依赖 image_store）；KaleidoApp 加 layer_store()/panel_registry() accessor
- **PanelRegistry trait 上移 traits**（panel.rs），services 实现存 `Weak<Mutex<dyn Panel>>`——面板需要可变渲染，注册/查询都用 Mutex 包装

### C3 桌面端接线
- **right_panel.rs 重写**：① 面板来源 = PanelRegistry.panels() 实时读取 ② **交互接线**——NumberInput(−/+步进)、Checkbox(点击切换)、Dropdown(点击循环)、ColorPicker(点击循环 9 预设色)、ButtonRow(按钮) 全部回调 Panel::on_change/on_button + `this.update(cx, notify)` 刷新 ③ 右侧「图层」区：真实图层列表（可见性●○ + 名字 + 透明度%，活动层高亮），点击切换活动层，「+」新建图层
- **toolbar.rs**：点击工具 → supports_layers() ? apply_to_document(LayerToolContextImpl) : 原单图路径（apply_mutation + TileSnapshotCommand undo）
- **app.rs**：启动/打开文件 → `layer_store.import_image("背景", img)`；注册 solid-layer 双份句柄（Arc<dyn Tool> + Arc<Mutex<dyn Panel>>）
- **GPUI 坑**：`cx.entity()` 拿 Entity<Self> 用于闭包回调 notify；闭包内不能用 &Theme（借用）——颜色值提前提取；`Button::small()` 不存在

### C4 示例插件 solid-layer（plugins/examples/solid-layer）
- 同时实现 Tool（supports_layers + apply_to_document 添加纯色层）+ Panel（ColorPicker + NumberInput 透明度 + ButtonRow 添加图层）
- 插件持有 Arc<dyn LayerStore>（构造注入）；on_change 更新 color/opacity，on_button("add") 直接 add_solid_layer + set_opacity
- derive Clone（tool/panel 各持一份句柄）
- 验证：`cargo run -p kaleido-desktop` → 右侧面板见 solid-layer 控件 → 点「添加图层」画布出红色纯色层 → 图层列表多一行
